# ShelterConnect

An independent agentic website for emergency shelter management. It is one of the five
sites of the [ReliefMesh](../../README.md) demonstration and follows the
[Open Agentic Web MVP specification](../../docs/worldwide_agentic_web_mvp_spec.md).

**All data is simulated demonstration data.** No real shelter, person or stock level is shown.

## What it does

- Registers emergency shelters and publishes their capacity, occupancy and urgency.
- Publishes resource requests (requirement, stock on hand, shortage, needed-by time).
- Updates shelter inventory.
- Receives delivery receipts from a coordinating site, confirmed by a person here.

## Run it

Static site, no build step, no dependencies. From the repository root:

```shell
node vendor/agentify-website/scripts/serve_site.mjs sites/shelterconnect --port 8081 --open-as localhost
```

Open http://localhost:8081/. `npm run serve` at the repository root starts all five sites.

## Agent network

| | |
| --- | --- |
| Network URL | `http://localhost:8081/shelterconnect` |
| Front agent | `ShelterStatusAgent` |
| Specialists | `ShelterRequestAgent`, `ShelterInventoryAgent` |
| Source of truth | [`shelterconnect.hocon`](shelterconnect.hocon) → `shelterconnect.network.json` (generated) |
| Manifest | [`agent-manifest.json`](agent-manifest.json) |

The assistant on the page runs in the visitor's browser with the visitor's own LLM key
(⚙ AI model settings). It sends the visitor's messages, and the page data it reads, to the
provider the visitor picks. To stop using a key: **Delete setup** under Advanced settings,
then close the tab.

### Actions

| Action | Effect | On the page | Shared with partner sites |
| --- | --- | --- | --- |
| `get_shelter_overview` | read | yes | yes, hidden frame |
| `get_resource_requests` | read | yes | yes, hidden frame |
| `get_shelter_inventory` | read | yes | yes, hidden frame |
| `update_inventory` | write | yes | no |
| `publish_resource_request` | write | yes | no |
| `set_shelter_urgency` | write | yes | no |
| `register_shelter` | irreversible (confirmation dialog) | yes | no |
| `record_deliveries` | irreversible | no | yes, in a ShelterConnect window where a person confirms |

Shared actions are limited to the exact origins in [`js/site-links.js`](js/site-links.js)
(`CALLERS`). The write is never shared with `"*"`.

## Linked site

- **ReliefMesh Command** — `http://localhost:8080/reliefmesh_command`. The assistant can
  ask it what it can coordinate for open requests.
- Before anything is sent, the visitor sees a consent card with the partner's name, its
  host and the first 140 characters of the request. **Always allow** skips the card for
  that host until the page is reloaded.
- A request contains only shelter-level facts. The assistant is told never to put names,
  emails, phone numbers or booking codes in it; the runtime does not filter it, so the
  visitor checks it on the card.
- The partner's network runs in this browser on the visitor's key, with only the actions
  the partner's bridge shares with this site. A call costs more than the card's estimate.

## State and static hosting

State lives in this origin's `localStorage`. A partner site reads it through a hidden
frame on this origin. Browsers partition a frame's storage when the embedding site is on
a different registrable domain, so a partner there sees the published seed plus its own
partition rather than edits made on this page. Sites on the same registrable domain
(all `localhost` ports locally, or subdomains of one domain) share it. A production
deployment would keep this state on ShelterConnect's own server.

## Files

```text
index.html, styles.css, favicon.svg   the page
js/shelter-data.js                    simulated seed data and the resource catalogue
js/shelter-store.js                   business rules and storage (no DOM)
js/app.js                             the page; exports App.page
js/site-links.js                      partner addresses and allowed caller origins
site-actions.js                       the page's actions (website_* tools)
site.js                               mounts the assistant, with the confirmation dialog
bridge/bridge-actions.js              the reads shared with partner sites
bridge/delivery-window.js             the shared write, confirmed in this site's window
bridge/action-bridge.html, bridge/agent-manifest.json   generated by the official build
shelterconnect.hocon                  the agent network (source of truth)
shelterconnect.network.json, agent-mcp.json, .well-known/   generated; do not edit
agent-manifest.json, links.json       public bundle files
runtime/                              the official browser runtime, unchanged
tests/                                Node tests
_headers, vercel.json                 static-hosting headers (CORS on public agent files)
```
